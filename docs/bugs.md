# Bug 台账（防"重复修 / 回归丢失"机制）

> 建立原因（2026-10-29 用户质询"修好的 bug 怎么又让我修一遍"）：
> 之前的修复只存在于对话记忆，回退/合并/cherry-pick 时修复会静默丢失（实例：思考初期"固定 Thinking"
> 在回退 1.7.5 时随 fix3-7 被丢弃，1.7.14 才重新修）。
>
> **规则**：
> 1. 任何回退 / 合并 / cherry-pick 前，对照本表逐条确认每个修复的去向（保留 or 明确丢弃）。
> 2. 新报障先查本表：现象吻合 → 按"修复 commit"查该代码是否还在，**先查丢失点，不要当新 bug 修**。
> 3. 每修复一个 bug 追加一行，验证通过后更新"验证状态"。
