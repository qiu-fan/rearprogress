# 正面显示管线 — 现状与重构基准
> 2026-10-30 Forge 梳理。背景：正面岛显示逻辑经四个时期补丁叠加，用户判定"一团糟"，开 refactor 分支收敛。本文档用行为语言描述，不需要懂代码。

## 1. 标题（大岛左侧文字）当前的 7 级优先级
从上到下，命中即停：

| 级 | 条件 | 显示 | 来历 |
|---|---|---|---|
| 1 | 工具名 2 秒锁（刚调工具的头 2 秒） | 工具名 | fix15：防工具期标题闪烁 |
| 2 | 自适应显示激活（解析到特定工具参数，如 logcat 命令） | 自定义文案（如 Logcat/Compiling） | 早期功能 |
| 3 | AI 自定义标题 + 距上次工具>3秒 + 非 Thinking 类 | AI 给的标题 | AI 主动上报 |
| 4 | **执行窗口内**（命令带 timeoutMs，从调用起算） | 工具名 | 今日新增（用户令） |
| 5 | 距上次工具>3秒 且 (token 在涨 或 正在运行+10秒内思考过) | Thinking | fix13/14/16 叠加 |
| 6 | 有工具调用记录 | 最近工具名（文件类追加 diff 统计） | 基础功能 |
| 7 | 兜底状态 | Agent / 任务进行中 / 已完成 | 基础功能 |

## 2. 展开态大标题（下拉卡顶部）的独立优先级
| 条件 | 显示 |
|---|---|
| 执行窗口内 | Agent \| 执行中（今日新增） |
| 距上次工具>10秒 且 思考中 | Thinking |
| 距上次工具>10秒 且 空闲 | Agent \| 已就绪 |
| 5秒内工具≥2次 | X.Xs/次（调用频率） |
| 否则思考中 | Thinking |
| 否则 | Agent \| 已就绪 |

⚠️ **已知不一致**：标题用 3 秒门槛、展开态用 10 秒门槛；两套判断各写各的，是"正面无跳点背屏有"类怪像的温床。重构要统一到一张表。

## 3. 跳点与转轮（SystemUI 侧引擎，独立于上面两表）
- 跳点：捕获标题视图（内容恰好是 Thinking）→ 每秒写 Thinking./../... 循环；防自续命靠精确匹配+自写标志
- 转轮：捕获 token 行视图（↑↓开头）→ 尾部交替写 ◄/►
- 引擎只在视图 attach 时写；通知不更新时背屏冻结（用户已确认接受）
- ⚠️ **已知冲突**（今日引入）：执行窗口让标题长期=工具名 → 引擎捕不到 Thinking 视图 → 正面跳点在连续工具期几乎不出现。修复方向：工具返回即结束窗口（待 OperitHook 一行回调，3.4）

## 4. 刷新触发链（什么时候推新画面）
工具开始/结束、token 推送（活跃期约100ms节流）、心跳、看门狗超时、AI 上报。**没有事件就没有刷新**——背屏冻结的原因。

## 5. 并发切换（双 AI 同时干活）
现状：两个对话抢同一个通知，最后推送者胜出 → 画面来回跳（用户已确认这是主要困扰）。
**新需求（用户拍板）**：进行中的任务按对话 id 分配稳定短名（A/B/C…），标题左侧加 `A:` 前缀，让切换可辨识。待调研模块能否拿到对话粒度信息。

## 6. 重构目标（验收标准）
1. 标题与展开态共用一张优先级表，同进同出（消灭 3s/10s 不一致）
2. 优先级表写成一处可读的清单，增删规则改一处生效
3. A:/B: 对话前缀落地，双 AI 并发时可辨识
4. 现有行为除已确认修改项外保持不变（单步改-验-提交）
